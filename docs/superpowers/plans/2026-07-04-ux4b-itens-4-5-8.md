# UX 4b — Itens 4, 5 e 8 (undo no drag, coluna colapsável, nota com template)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Três melhorias de QOL no Kanban/painel do lead: desfazer arrasto de etapa via toast, colapsar colunas do funil (com contadores visíveis), e nota rápida por template no painel do lead.

**Architecture:** Só frontend (Vue 3 `<script setup>` + Vuex), zero migração e zero backend. O toast nativo (`useAlert` → `Snackbar.vue`) ganha suporte a botão com callback; o undo re-despacha `leads/move` com a etapa/posição anteriores. Colapso é estado local do `KanbanColumn` persistido em localStorage (padrão `FILTERS_KEY` do leads.js). Template de nota é um `<select>` nativo que preenche o textarea existente do `LeadFields.vue` (compartilhado por gaveta e painel da conversa).

**Tech Stack:** Vue 3, Vuex, vuedraggable, Tailwind, vitest (@vue/test-utils), i18n `RAMON.*`.

- **Tailwind only** — sem CSS custom, sem scoped, sem inline style (AGENTS.md).

- **Sem ambiente local completo** — validação final é PR + CI. Vitest local funciona (`npx pnpm@10.2.0 install` na worktree se `pnpm` falhar). Erros eslint `Delete ␍` em arquivos NÃO tocados = CRLF do checkout Windows, ignorar (CI Linux é a verdade).

Em `KanbanBoard.vue`:

```js
// novo import no topo:
import { useAlert } from 'dashboard/composables';

// onMove vira async e ganha o undo no caminho simples:
const onMove = async ({ id, leadStageId, newIndex }) => {
  const stage = findStage(leadStageId);
  const lead = findLead(id);
  if (stage?.is_lost && !lead?.lost_reason) {
    pendingMove.value = { id, leadStageId, position: newIndex };
    lostModalOpen.value = true;
    return;
  }
  if (stage?.is_won && !lead?.value) {
    pendingMove.value = { id, leadStageId, position: newIndex };
    wonModalOpen.value = true;
    return;
  }
  // Guarda a origem ANTES de persistir, para o desfazer do toast.
  const previous = { leadStageId: lead?.lead_stage_id, position: lead?.position };
  await store.dispatch('leads/move', { id, leadStageId, position: newIndex });
  if (previous.leadStageId && previous.leadStageId !== leadStageId) {
    useAlert(t('RAMON.KANBAN.MOVE_DONE'), {
      type: 'button',
      message: t('RAMON.KANBAN.MOVE_UNDO'),
      duration: 5000,
      onClick: () =>
        store.dispatch('leads/move', {
          id,
          leadStageId: previous.leadStageId,
          position: previous.position ?? 0,
        }),
    });
  }
};
```

Nota: o toast só aparece quando trocou de coluna (`previous.leadStageId !== leadStageId`) — reordenar dentro da mesma coluna não pede undo.

```js
// Persistência do colapso por etapa (mesmo padrão do FILTERS_KEY em leads.js).
const COLLAPSED_KEY = 'ramon_kanban_collapsed';
const readCollapsed = () => {
  try {
    return JSON.parse(localStorage.getItem(COLLAPSED_KEY) || '[]');
  } catch (e) {
    return [];
  }
};
const collapsed = ref(readCollapsed().includes(props.stage.id));
const toggleCollapsed = () => {
  collapsed.value = !collapsed.value;
  try {
    const ids = readCollapsed().filter(id => id !== props.stage.id);
    if (collapsed.value) ids.push(props.stage.id);
    localStorage.setItem(COLLAPSED_KEY, JSON.stringify(ids));
  } catch (e) {
    // localStorage indisponível: seguimos sem persistir
  }
};
```
